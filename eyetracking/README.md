# Eye-tracking: segmentation, pipeline and analysis

The scripts here label what participants looked at in the films and produce the encoding eye-tracking statistics and figures in the paper.

## Groups and outcome

Eye-tracking analyses compare three groups:

| Group | Who | n in the encoding sample |
|---|---|---|
| `Spy_Pro` | Proactive spy | 16 |
| `Crim_Pro` | Proactive criminal | 13 |
| `Control` | Retroactive spy, retroactive criminal and neutral | 50 |

The main outcome is a bias score, `(face - place) / (face + place)`, from -1 (only places) to +1 (only faces). It is computed per film viewing from fixation count, fixation duration and raw sample proportion.

## How the data flow

1. **Label the films (computer vision semantic segmentation).** The films are split into frames, and a scene-segmentation model (CSAIL ADE20K) assigns every pixel of every frame to one of 150 classes, such as person, wall or chair. The result is one label mask per frame (1920 x 1080 px).
2. **Map gaze onto the labels (pipeline).** For each gaze sample and fixation, the pipeline finds the corresponding frame on screen at that timepoint and reads the segmentation label of the pixel at the gaze coordinates. The 150 classes are then grouped into personal, spatial, object and other (`pipeline/category_mapping.xlsx`), which gives a record of what was viewed, moment by moment.

The output of step 2 is the BIDS derivatives in the data deposit, separated into fixations, saccades and raw samples. The statistical analyses start from there.

## Folders

| Folder | Contents |
|---|---|
| `segmentation/` | Extract film frames, assign semantic categories, convert the masks (csv files) to PNGs |
| `pipeline/` | Map raw gaze onto the labels and write the BIDS derivatives |
| `analysis/` | Statistics: `encoding_bias.py`, `encoding_search_breadth.py` and `helper.py` (loading, running R, logging, plotting) |

## Running from the data deposit

Set `DATA_ROOT` and `RSCRIPT` in `config.py` (see the main README), then run:

```bash
cd eyetracking/analysis
python encoding_search_breadth.py
python encoding_bias.py
```

Paper figures are written to `RESULTS_DIR` (by default `results/`). Logs, contrast tables and exports go to `RESULTS_DIR/eyetracking_results/`.

## Running from films and raw recordings
Added for reference: this needs the films and raw `.asc` eyelink file recordings, which are not made public.

Should you decide to try the segmentation for yourself, install the model code at the commit used here, and get `encoder_epoch_50.pth` and `decoder_epoch_50.pth` from `segmentation_weights.zip` in the data deposit. These are CSAIL's original weights, redistributed under their BSD 3-Clause licence as the original download site (<http://sceneparsing.csail.mit.edu/model/pytorch/ade20k-resnet101-upernet/>) was unreachable in November 2026. Put them in the folder set as `SEGMENTATION_WEIGHTS_DIR` in `config.py`. The model is ResNet101-UPerNet (ADE20K, epoch 50).

```bash
pip install git+https://github.com/CSAILVision/semantic-segmentation-pytorch.git@8f27c9b97d2ca7c6e05333d5766d144bf7d8c31b
```

Then, from the repository root:

```bash
python eyetracking/segmentation/extract_frames.py             # extracts every .mp4 in VIDEO_DIR
python eyetracking/segmentation/segment_frames.py
python eyetracking/segmentation/convert_masks_to_labels.py    # mask CSVs -> label PNGs, which the pipeline reads, about 20-40x faster
cd eyetracking/pipeline
python pipeline_runner_stream.py --force
```

Each participant takes about 10-15 minutes with label PNGs. Setting `--participants 001_01` limits the run to one recording, and `--resume` continues an interrupted run.

## Statistical Models

The main model, fitted separately for each gaze measure with REML and Satterthwaite degrees of freedom:

```
Bias_Score ~ Group * Block + Film + (1 | Participant) + (1 | Participant:Block) + (1 | Participant:Film)
```

Each log file also reports sensitivity models with other random-effects structures.

The models are fitted in R (lme4, lmerTest, emmeans), called from Python, for Satterthwaite degrees of freedom and Tukey-adjusted contrasts; these are the same packages as in the behavioural analyses. The R code is written out in full inside the Python scripts: `_R_MODEL_TEMPLATE` (main model, Section 6), `_R_SANITY_TEMPLATE` (retroactive groups vs control, Section 7) and `_R_PLOT_CONTRASTS` (contrasts drawn on the figures) in `encoding_bias.py`, and `_R_MODEL_TEMPLATE` in `encoding_search_breadth.py`.

## Exclusions

Of 100 participants, 5 had no usable recording and 16 were excluded, leaving 79. `study_info/exclusions.csv` in the data deposit lists each one.

- **Out-of-bounds gate:** participants with 10% or more of fixations or samples off-screen. It flags 11 participants and is recalculated on every run of `encoding_bias.py`.
- **Manual list:** 9 participants, 4 of whom the gate also flags. These include cases of calibration drift that stay on-screen and so pass the gate.

`encoding_search_breadth.py` uses a fixed copy of the combined list, because it does not load the sample files the gate needs.

## Methods details

- **Reproducibility:** the analysis scripts reproduce the statistics reported in the paper. This was checked with R 4.4.1 (lme4 2.0.1, emmeans 2.0.3) and R 4.6.1 (lme4 2.0.6, emmeans 2.0.4), which agree to within 1e-12. Figures can differ by small rendering details between matplotlib builds and systems, and the radar figure's layout depends on the matplotlib version, so use the pinned 3.10.6.
